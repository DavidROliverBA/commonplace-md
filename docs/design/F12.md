# F12 — Notion-style `/` menu and `+` block handle

_The design as agreed before it was built. Done: see [CHANGELOG.md](../CHANGELOG.md); what's still open is in [BACKLOG.md](../BACKLOG.md)._

**Size** M, in two steps · **Evidence** `web/components/Editor.tsx:283` (autocompletion already
runs wikilink and tag sources); CodeMirror and Markdown editor research (2026-10-11), below

Notion has two ways to insert and arrange content without remembering markdown: typing `/` opens
a searchable menu of blocks (heading, list, to-do, table, callout, picture…), and hovering a
block shows a `+` (insert below) and a `⋮⋮` handle (drag to move, click for "turn into",
duplicate, delete).

**Does CodeMirror support it?** Yes for the `/` menu, and not built in but feasible for the
handle:

- **`/` menu: built in.** `@codemirror/autocomplete`, which Commonplace already uses for `[[`
  and `#`, takes a custom completion source; a third source that fires on `/` at the start of
  a line or after a space is the whole mechanism, and its `snippet()` helper gives tab-through
  placeholders (a table's cells, a link's text). At least one popular Markdown editor built on CodeMirror 6 ships
  exactly this as a core Slash commands plugin (`/` at line start or after a space, fuzzy
  search, Esc or Space to dismiss).
- **`+` and `⋮⋮` handle: not built in.** CodeMirror has no notion of blocks or a hover handle,
  and its maintainer's answer to "drag from the gutter" is to build it from events. But the
  pieces exist: `view.lineBlockAtHeight` / `posAtCoords` find the line under the pointer, the
  markdown syntax tree gives the block around it (a list item with its children, a fenced
  code block, a table, a quote), and a ViewPlugin can float one handle element beside it.
  Several editor plugins prove it on CodeMirror 6: Notion Block and Feel the Notion (`+`,
  drag handle and insert menu), Dragger and Block Drag & Drop (drag only).
- **Different from Notion underneath.** A note stays plain markdown; "blocks" are worked out
  from the syntax tree each time, never stored. Nothing changes in the database or export.

1. **`/` menu (S). Done 2026-10-11 (Milestone A).** A slash completion source in `Editor.tsx`: headings 1–3, bullet,
   numbered and to-do lists, quote, callout (with type), table, code block, divider, picture
   (the existing picker, `insertFiles`), link to a note (`[[`), property (`addProperty`),
   today's date; later embed (F2) and templates (F3). It doesn't open inside code, frontmatter
   or a URL (`/` in `https://` or `a/b` stays a slash), and typing `/` then a space just types
   a slash. The chosen item replaces `/query` in one change, so it merges with live edits.
   Works on the phone (the iOS keyboard has no Ctrl-Space, so `/` is the way in there).
2. **`+` and `⋮⋮` handle (M). Done 2026-10-12.** On desktop the handle follows the pointer down the left
   margin; on the phone, with no hover, it shows beside the block with the cursor.
   - `+` inserts an empty line below the block and opens the `/` menu.
   - `⋮⋮` click: turn into (paragraph, heading, list, to-do, quote, callout), duplicate,
     delete, and copy a `[[Note#heading]]` link for headings; F10's colours later.
   - `⋮⋮` drag moves the whole block (a list item takes its children, a heading only its own
     line, a table or code block as one), with a drop line between blocks; mouse after 5px,
     touch after a 400ms long press, as in the file tree (`web/lib/useTreeDrag.tsx`).
   - Works on Live Preview's block widgets (tables, the properties panel is excluded) and in
     source mode, not in read mode.

**One risk to test.** A move is a delete plus an insert, so if a collaborator is typing inside
the block at that moment, their keystrokes land in the deleted copy and are lost. Rare in a
personal vault; check it in the two-browser test and, if it bites, refuse a move while a remote
cursor is inside the block.

**Done when** typing `/tab` and Enter inserts a table with the cursor in its first cell, on the
laptop and the iPhone; `/` in a URL or code block does nothing; a list item with sub-items
drags to a new place in one piece, and undo puts it back; and both work while another person
edits the same note.
